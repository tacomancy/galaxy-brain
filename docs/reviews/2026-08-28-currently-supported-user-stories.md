# Currently supported user stories

Date: 2026-08-28  
Reviewed revision: `e8c0bc38c83286a333092c2848bd2a5b39c7e0dd` (`app` version `0.7.0`)  
Scope: the committed desktop application, its public module interfaces and adapters, its automated tests, and version-matched project documentation.

## Research question and support threshold

This review asks: **Which user outcomes does the application actually support at the reviewed revision?**

The stopping condition was a complete pass through the production source roots, the packaged desktop workflow tests, the module and adapter tests, and the documentation that records implementation status. A story is classified as:

- **Desktop-supported** when it has a production path through the renderer, preload bridge, main process, modules/adapters, and direct packaged-workflow evidence.
- **Module-supported only** when the behavior is implemented and tested through a public module or adapter contract but has no complete desktop interaction.
- **Not currently supported** when it exists only in product decisions, architecture, a prototype, an implementation brief, an incomplete tracer bullet, or an absent production adapter.

This is intentionally narrower than the accepted V1 product scope. Product Decisions describe the intended V1 experience, including capabilities that the code map and delivery plan still mark unimplemented or deferred ([Product Decisions, V1 scope](../architecture/v1-ui/product-decisions.md#L51-L55); [Code Map module status](../architecture/v1-ui/code-map.md#L48-L57)). The standalone prototype is explicitly throwaway comparison material rather than production behavior ([prototype README](../../prototype/knowledge-workbench/README.md#L1-L9)).

## Current project structure

The project has a clear production dependency path: React UI adapters call a typed preload bridge, validated Electron main-process handlers call framework-independent application modules, and modules depend on file-backed or fixture adapters ([Code Map, dependency direction](../architecture/v1-ui/code-map.md#L18-L32)). The current implementation is organized as follows:

- `app/src/renderer/` contains the three production workspace views—Atlas, Studio, and Paper Desk—and the shared workspace switcher.
- `app/src/preload/` exposes narrow operation-specific desktop calls; it does not expose filesystem or raw IPC access ([workbench bridge](../../app/src/preload/workbench-bridge.ts#L1-L71)).
- `app/src/main/` composes the file-backed repository, session-state, annotation, and Synthesis-result adapters and validates each IPC operation ([main composition and bridge handlers](../../app/src/main/index.ts#L108-L202), [repository operations](../../app/src/main/index.ts#L217-L327), [Synthesis operations](../../app/src/main/index.ts#L330-L515)).
- `app/src/modules/` currently contains Workbench Session, Source Processing, and an early Governance module. Knowledge Authoring, Discovery, and Learning modules remain absent/unimplemented ([Code Map](../architecture/v1-ui/code-map.md#L48-L57)).
- `app/src/adapters/` contains production file-backed repository, session-state, annotation, and Synthesis-result storage; PDF support is a fixture adapter, the model adapter is absent, and Governance is in-memory only at the reviewed revision ([Code Map, adapters](../architecture/v1-ui/code-map.md#L71-L81)).
- `app/templates/knowledge-repository/` is the empty starter copied when creating a repository, while `app/tests/fixtures/knowledge-repository/` is synthetic test data and not user knowledge ([project structure](../../README.md#L22-L32); [starter inventory](../architecture/v1-ui/starter-inventory.md#L1-L49)).
- `app/tests/workflows/` contains packaged Electron behavior tests. Lower seams live in `app/tests/source-processing/`, `app/tests/governance/`, and `app/tests/contracts/` ([Code Map, test roots](../architecture/v1-ui/code-map.md#L34-L46)).

## Implemented foundations that are not complete desktop user stories

These behaviors are real code with direct tests, but describing them as generally available end-user workflows would overstate the application.

| ID | Implemented behavior | Why it is not a complete supported desktop story |
| --- | --- | --- |
| US-M01 | **Capture one located source claim as a portable Structured Annotation and reopen it from file-backed Working Material.** | Source Processing validates a locator, resolves a fixture passage, assigns source-claim attribution/classification, and persists it ([module implementation](../../app/src/modules/source-processing/index.ts#L528-L590); [behavior tests](../../app/tests/source-processing.test.ts#L32-L125)). The only PDF adapter is the deterministic fixture adapter, and Paper Desk has no import, text-selection, or capture controls; production PDF import/rendering/relinking are deferred ([Code Map](../architecture/v1-ui/code-map.md#L75-L80)). |
| US-M02 | **Prepare, confirm, and transiently return a Synthesis draft through an injected model adapter, with exact-payload confirmation semantics.** | Public Source Processing tests prove a mock model receives only the confirmed payload and that decline/cancel makes no request ([tests](../../app/tests/source-processing/prepare-synthesis-preview.test.ts#L238-L374)). The production main process composes no model adapter and therefore can only return `agent-provider-unavailable` ([main](../../app/src/main/index.ts#L440-L448)). |
| US-M03 | **Explicitly save Synthesis results with provenance; optionally retain a concise prompt/context snapshot; check or refresh source identity; regenerate, restore, and human-edit versioned results; persist the history in portable files.** | These operations are part of the public Source Processing interface ([interface](../../app/src/modules/source-processing/index.ts#L352-L393)), have focused behavior tests ([test inventory](../../app/tests/source-processing/prepare-synthesis-preview.test.ts#L431-L1320)), and have a file-backed round-trip contract ([contract](../../app/tests/contracts/synthesis-result-repository.test.ts#L104-L208)). | US-M04 | **Create a manually authored exact-change Proposal, record an accepted exact-version Judgment, apply it, and retain the previous governed version in memory.** | The S2 Governance test proves the current version is unchanged until application and the prior version remains retrievable afterward ([test](../../app/tests/governance/apply-governed-change.test.ts#L60-L179)). ## Proposed, prototype-only, or incomplete stories

The application does **not** currently support these user stories end to end:

- Author or autosave general Working Material in rich and equivalent extended-Markdown source views. Knowledge Authoring is unimplemented ([Code Map](../architecture/v1-ui/code-map.md#L52-L55)); Studio currently presents context and saved material but has no editor ([Studio](../../app/src/renderer/studio/Studio.tsx#L396-L464)).
- Import, manage, link, render, select arbitrary text in, annotate, or relink real PDFs. Paper Desk labels its view as a fixture preview and the production PDF engine remains unselected ([Paper Desk](../../app/src/renderer/paper-desk/PaperDesk.tsx#L49-L78); [Code Map](../architecture/v1-ui/code-map.md#L78-L80)).
- Send a real OpenAI API request, configure a working provider in-app, receive a live Synthesis result, or save/regenerate/edit that result through the desktop UI. The Model adapter is unimplemented and the accepted TB7 surface intentionally stops at provider-unavailable ([Delivery Plan](../architecture/v1-ui/delivery-plan.md#L389-L398)).
- Review and durably apply Proposals through a desktop route, with audit records, rollback bytes, fingerprint rechecks, and interrupted-transaction recovery. TB8 has only the in-memory S2 slice and remains pending acceptance; the dedicated Proposal Review UI is unimplemented ([Delivery Plan](../architecture/v1-ui/delivery-plan.md#L400-L423); [Code Map](../architecture/v1-ui/code-map.md#L68-L80)). The Repository Format's applied-Proposal section is an accepted persistence contract, not proof that its adapter is already present ([Repository Format](../architecture/v1-ui/repository-format.md#L32-L105)).
- Search, Ask, Jump, learning routes/progress, generated relationships, or actionable Atlas judgment queues and metrics. Discovery and Learning are unimplemented, and the richer Atlas stories remain later tracer bullets ([Code Map](../architecture/v1-ui/code-map.md#L56-L68); [Delivery Plan](../architecture/v1-ui/delivery-plan.md#L443-L459)).
- The complete V1 desktop quality/recovery contract, including broad external-edit detection, governed rollback, complete keyboard workflows, reduced motion, scalable text, theme persistence, undo, and general artifact history. These remain planned under later tracer bullets and the release gate ([Delivery Plan](../architecture/v1-ui/delivery-plan.md#L467-L495)).
- Tablet, phone, non-PDF viewers, remote sync/backup, GitHub integration, demo mode, multi-repository operation, other providers, dynamic model selection, or arbitrary inline outbound-payload editing. These are explicitly deferred or future work ([Product Decisions](../architecture/v1-ui/product-decisions.md#L131-L152)).

## Evidence quality and documentation tensions

**Established fact:** the committed revision passes the repository's normal verification gate in an isolated snapshot: formatting, lint, strict TypeScript checking, and 60 Vitest tests all passed. The packaged desktop suite could not be rerun in the restricted environment because Electron Forge attempted to resolve `github.com`; the version-matched delivery record reports the accepted TB7 packaged suite passing 21 WebdriverIO specs ([Delivery Plan](../architecture/v1-ui/delivery-plan.md#L389-L397)).

**Inference — agent:** the most honest product summary today is: **a local macOS repository navigator and evidence-review Workbench with strong safe-open/resume behavior, contextual Atlas/Studio/Paper Desk navigation, fixture-backed source reading, and a provider-free Synthesis consent/history surface.** It is not yet a complete knowledge authoring, real-PDF, live-agent, governance, discovery, or learning application.

The documentation contains two tensions readers should keep in mind:

1. Product Decisions are authoritative for intended V1 behavior, not for current implementation. For example, they describe deep PDF support, full authoring, governance, Search/Ask/Jump, autosave, undo, and accessibility requirements that the code map and delivery plan still defer ([Product Decisions](../architecture/v1-ui/product-decisions.md#L68-L128)).
2. The Repository Format now specifies the first file-backed Governance persistence representation ([Repository Format](../architecture/v1-ui/repository-format.md#L32-L105)), while the reviewed committed code contains only the in-memory Governance adapter and the delivery plan still requires the S5 file-backed cycle before TB8 is complete ([Delivery Plan](../architecture/v1-ui/delivery-plan.md#L408-L423)). Treat the schema as an accepted implementation contract, not as evidence of shipped behavior.

## Conclusion

Thirteen user stories are supported through the packaged desktop path, centered on safe local repository lifecycle, exact-session resume, explicit context selection, three-workspace navigation, source-claim inspection/reading-position restore, Synthesis payload consent, graceful provider absence, and saved-result history restore. Three broader Source Processing capabilities and one early Governance capability are implemented behind tested module interfaces but are not fully available to desktop users. The remaining product narrative is chiefly accepted V1 direction or later tracer-bullet work rather than current application support.
